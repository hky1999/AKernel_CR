# gVisor 原生克隆函数的独立远端验证

此目录仅保留实际执行的函数质量门，不是完整 runsc 部署或 SDK 验收。产品候选在独立组件工作树，基于 `.5` 精确源码 87e8441b6，尚未提交/交付。候选完整源码与 bundle 通过后才能按精确提交独立重放；本材料不声称外部已可获取完整新 gVisor 实现。

helper-driver01.py 严格等待 FC 正式十组二十实例成功、native 布局和空 Environment，随后才启动 2 CPU/2 GiB、任务私有网络/挂载/cgroup 的 Go1.25.5 容器；依赖 x/sys v0.43.0 和原 go.sum。三个函数回归轮次启用 race，另在两个真实 JuiceFS 客户端各跑三轮，覆盖匿名文件、未同步 mmap、克隆后写入/截断不影响父文件，以及短复制/中断/错误边界。两端临时二进制/目录清理，ELF 5605d610… 和源摘要见同日 gvisor-native-clone-helper01.json。

helper-qa01.sh 仅格式化已登记候选文件，再复制克隆函数/回归到独立模块编译测试。不能把其他文件“被格式化”当作 SnapshotToFd、采纳和 seccomp 已经编译验证。完整 Bazel/匹配 bundle、后台恢复到外部捕获的顺序、sandboxd 专有目录与 SDK 仍未通过。

脚本包含原任务固定路径、PID/start_ticks 依赖和输出目录；新环境必须另存唯一任务身份，不能在共享服务器照抄、跳过身份检查或覆盖原输出。只在远端运行，原始配置/凭据/运行时输入压缩包和二进制不入父仓。
