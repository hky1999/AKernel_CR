# gVisor 原生私有文件布局的分支与重启检查

## 1. 问题

继续既定计划：核心SDK已经通过，补同一快照的独立恢复分支、持续写/再次保存，以及新布局中的控制进程重启和读者保护。编译测试仅BareMetal独立环境，不修改共享服务；不能以旧布局证据代替新布局。

## 2. 方法

只读重验五Pod、两端15实际制品、可路由/可调度及空Environment；沿用gVisor218d85378/sandboxd21fb466和完整已测字节，未编译、换包或部署。新增gvisor-native-extended01，复用已有64MiB普通文件、128MiB稀疏文件、4MiB mmap、1MiB打开后删除文件和重命名仍打开的FD测试；通过公共SDK与既有Environment快照API驱动，不新增catalog。

本轮恢复两个分支而非把仍运行的生产者算成第二个恢复者。分支写入不同代次，源继续写入第三种内容，各自再次保存恢复；关闭一个分支后再次从原快照创建校验者，确认原数据未变。另准备重启探针，区分正常unlink的匿名私有副本和仍须保有名字的不可变检查点输入。

## 4. 结论

【实测】当前原生gVisor布局通过同一快照的两个恢复分支、多代次独立写、再次保存恢复及原快照重新读取验证。

【源码/探针适配】原探针把共享挂载下所有“名字不存在”的FD都判错，在原生布局会误报正常的匿名私有文件。新探针只对已验证的私有后端inode接受unlink，要求设备、目录、nlink=0，并对真正的检查点输入继续验证名字及inode对应关系；不能把匿名副本位于某artifact目录当成后台输入仍在读取的证据。

【只读实测】restart01 的另一个探针问题是仅凭实际可执行文件名也纳入运行时：一个 `runsc-sandbox` 主进程和 argv 为空的 gVisor 辅助子进程都使用 `gvisor_sentry`，且共用 FD。失败发生于“应有一个运行时”断言，未创建角色崩溃记录、未发送信号。restart02 改为主进程 argv 与实际 ELF 同时匹配；保留原始失败及 /proc 分类证据，不放宽匿名文件或输入文件身份断言。

【实测】普通重启三例全部通过；每例三次 checkpoint、两次 reload，验证 512 MiB 应用负载和 1 MiB 初始根文件。崩溃前再写入尚未 checkpoint 的独特根文件内容并修改内存，避免把“偷偷从旧版本重建”误判成原进程接管。匿名私有文件的设备号/inode、原运行时 PID/开始时间、SDK 对象身份与两份权威保护引用均不变。

【待实测】普通重启三例中真实旧页输入已经关闭，因此没有未结束后台读取结论。严格的 `pages.img` 输入屏障另存为 held-reader01，已在远端解析、固定 SHA 后启动；挂载/同步失败与性能配对也仍需后续结果，不能借本轮分支或普通重启通过一起关闭。

最新终态：held-reader02 的真实输入屏障已经成功，sandboxd 崩溃时仍打开一个命名页输入，同一读者三秒后恢复；但是原实例随后退出，SDK 整轮 rc=1，后续两个角色没有执行。因此严格重启保护未通过。源码只能确认 Wait 连接错误被转成 128，不能据此判断真实退出原因；详见 [独立失败检查](20261024T-pr119-gvisor-open-input-sandboxd-restart-failure.md)。只短停/恢复而不杀任何角色的 control02 对照 rc=0，同进程完整 1 GiB 内存、根文件、引用、忙删除和后续保存恢复通过，但在另一逻辑节点且是新快照，不是根因已经唯一定位。未改产品代码或运行字节。

严格输入首次尝试在信号前失败，未停止读者或杀角色。只读确认：Sentry 已隔离根目录，原始 JuiceFS 路径在其 `/proc/<pid>/root` 下不存在；同一目录在 sandboxd 根视图下存在，含 1089110016 字节 pages.img。helper01 使用了错误的名字查找视图，故“输入已关闭”文字不能证明当时后台读取结束。helper02 另存修正，使用目标 Pod 经容器身份和 ELF 核验的 sandboxd 根视图对命名输入与 Sentry FD 比较设备号/inode，保留输入严格匹配及所有信号身份检查。held-reader02 先完整核验并通过 SDK 删除首次失败资源，再重新验收，不混用两轮结果。

## 5. 建议与改进项

三个普通控制角色崩溃已完成。先定位真实页输入屏障与 sandboxd 崩溃组合的失败，按不杀角色的控制组区分屏障自身影响；不要放宽身份检查或把普通重启替代本例。修正并通过受影响门后，再做挂载和持久化失败，最后用同一代码交替比较本地 full 与 JuiceFS 原生克隆。若出现新产品改动，执行受影响的质量/SDK 门；不重复已经完成的 76 项。
