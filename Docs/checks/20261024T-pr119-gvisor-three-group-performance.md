# gVisor 私有存储介质与原生克隆：十组三配置性能检查

## 1. 问题

在PR #119的固定版本完整SDK、跨节点功能和原生私有层故障门通过后，区分“把正常写入搬到JuiceFS”和“保存时复用卷内克隆”各自的收益与成本。不得把不同运行时版本、内存恢复开关或失败/短停诊断混入性能样本。

正式实验、最终配置恢复与独立盘点均已通过，再在远端完成统计。30个实例、60次保存/reload全部通过完整状态校验，没有删除异常值或混入试跑。

## 2. 方法

BareMetal独立Kind/Pod环境；两个逻辑执行节点处于同一物理机。sandboxd91dff2f、gVisor218d85378；实际ELF43357403…/CRI0bde46ba…、完整六程序包63aa2353…，ADX/Execd/SDK与guest资产不变。没有提交后重建或切换正式默认后端。

| 配置 | 正常运行的私有文件数据 | 保存格式 | 分离的因素 |
|---|---|---|---|
| A | 本地XFS | full，完整保存 | 本地运行基线 |
| B | JuiceFS | full，与A相同 | A/B比较运行期介质 |
| C | JuiceFS | reflink配置，卷内克隆和独立私有文件清单 | B/C比较保存格式，A/C比较总效果 |

每实例1vCPU、2GiB内存配置、1GiB私有容量；应用占用512MiB确定性内存，根文件64MiB，另做64次4KiB随机写与fsync调用。每实例完成初次保存/reload、恢复后再次保存/reload，完整内存和文件校验。三配置先各一例试跑，再十组独立实例，共30实例/60次保存恢复；六种顺序轮换，节点按组交替，组内同节点配对。

每次部署验证新会话已注册、路由对应当前Pod、资源可调度且连续三次稳定，并核对运行文件15个SHA-256、控制Pod和Secret身份。两端任务JuiceFS客户端实际4GiB，缓存参数不变；每例检查工作进程/启动代次不变，OOM/oom_kill计数不增。宿主650GiB余量及实时Ceph容量设门。采样期间不编译、不故障注入、不清全局缓存。

本轮reload都在原逻辑节点；跨节点功能另有验收，不能把本表叫作跨物理机或对象全冷恢复性能。

源码口径：gVisor overlay新建文件转到tmpfs上层；`pkg/sentry/fsimpl/tmpfs/tmpfs.go:1288`的`fileDescription.Sync`、`filesystem.go:42`的`filesystem.Sync`均返回nil。普通应用fsync调用耗时因此不能等同宿主JuiceFS远端持久化耗时，也不直接横比FC ext4的fsync。真正checkpoint最终同步仍由既有保存/封存路径执行。

gVisor private RWFS保存为后端匿名文件，其数据介质由具体Sentry、沙箱标注、文件设备号/匿名属性共同确认。full本地模式可能显示内部`/filestore`别名；首次观测误判要求宿主路径相等，发生在保存之前，原件已保留。修正版只接受已确认别名，未取消设备和运行时身份检查。

## 4. 结论

【实测】直接将运行期私有文件搬到JuiceFS而继续完整保存（B）没有获得全面收益，普通写入更慢，第二轮恢复明显更慢且有额外PUT。原生克隆（C）改善了该退化，相对本地A的reload有小幅一致收益，但完整状态读取大致相近、checkpoint收益有限、首次应用停顿没有改善。该负载下不能据此把私有RWFS默认切换为JuiceFS。

【实测】C的请求仍约1.2–1.3秒，应用执行间隔仍约1.1–1.2秒，每轮仍有约540–603MiB PUT。只减少私有文件复制不能解决整个保存停顿；没有足够证据将剩余时间全归到某个内部阶段。

【源码】C仍用当前完整应用内存保存及后台恢复，不是内存增量保存，也不是远端基线＋本地差异层。普通写入、保存确认、目标首次可用和完整读取需要分开判断；文件数据克隆很快不代表整体checkpoint停顿已经达标。

## 5. 建议与改进项

保留C为已验收的可选候选，继续本地运行方案，不切换默认值。优先将“恢复时从远端只读基线按需读、写入进入节点本地差异文件”的真实候选纳入同样SDK/状态/读者生命周期验收；先验证成熟组件的可复用边界，不凭FD接口相同强行统一两运行时。另对B第二轮恢复期间231.44MiB PUT做逐对象/文件阶段归因，不能凭计数断言唯一原因。

对gVisor的内存完整捕获、最终同步与本地不可变暂存另建分相优化；不借存储后端切换顺便重写内存语义。客户端死亡/资源故障的因果隔离、4GiB仍触及上限的容量预算也须补齐。gVisor普通同步不保证整个私有文件树在运行时进程死亡后可独立恢复，不能将它当作应用共享卷的持久化语义。

“远端只读基线＋本地差异”仍需真正后端及完整SDK验收，不能用本地完整保存代替。还需客户端进程死亡、生产并发容量/HA、目标缓存冷读取等独立工作。本轮未同条件复测E2B、AgentEnv或Cube，不得据这些数值宣称超过竞品。
