# CrossNode 已验收源码交付阶段总结（2026-10-21）

## 阶段定位

本轮完成“把已验收实现整理成可获取源代码、固定组件组合和脱敏证据”的阶段性交付，不是生产发布，也不声称全新机器一键完整验收已经完成。

## 完成项

- ADX、公共 SDK、sandboxd 和 gVisor 的已验收源码分别提交到 GitHub 独立分支；Firecracker 固定到与实际旧验收 bundle 对应的现成源码。
- 五组件精确 gitlink、双 SDK 源码安装说明、JuiceFS 实验配置和辅助脚本、诊断验收脚本、门禁汇总与性能样本由新父仓统一管理。
- 原开发现场保留；未验收候选、私有凭据、运行数据、大型构建产物和内部父仓历史不混入交付。

## 关键数字前后对比

指标是公共 SDK 发起恢复创建到第一次实际业务就绪，同一物理机两个隔离逻辑节点，六组交替配对。Firecracker 中位数4.187秒→2.349秒，配对几何均值新/旧0.5600，六组均改善。gVisor 3.199秒→3.141秒，但95%区间0.6635–1.3051，收益未证。不是 guest checkpoint 停顿，也不是生产 P95/P99 或真实跨物理机冷恢复。

## 新知识与坑

- 编译源码、历史测试二进制和新构建产物必须分别记账；新 runsc 与历史摘要一致不等于新的全链路部署通过。
- SDK 源码扩展不能靠任意 PyPI 版本替代；ADX native 与公共 AKernel SDK 必须成对安装。
- 长测试目录会超过 Unix socket 108字节限制；使用私有 mount namespace 的短 /tmp，不应靠关闭隔离解决。
- 全工作区 ADX all-features 包含可选 AFS RDMA 构建；相关7组件严格 lint 通过不能改写为全工作区通过。

## 遗留清单

- 在全新独立环境完成固定版本部署和完整 SDK/读者安全退出/崩溃重启矩阵；补齐可移植全链路编排。
- 公共 failover/reload 组合验收、真实跨物理机与冷 S3 读取量、存储高可用及生产尾延迟。
- gVisor 进程级归因与稳定性对照；不以不显著作为零退化证明。
- 后续正式运行时发布、guest/initrd与模板兼容元组更新、产品部署需另过门禁。

具体版本、测试跳过与失败尝试见 VERSION.md、evidence/delivery-gates.json 和同日检查文档。
