# Firecracker 私有可写盘原生 JuiceFS 克隆功能验收总结

## 阶段定位与完成项

本阶段完成可选实验布局的功能门，不做默认生产后端裁决：FC 的 `overlay.ext4` 放 JuiceFS，guest 仍 ext4/virtio-blk；gVisor 私有层保持本地 XFS，内存和 ROFS 沿用已有机制。

源码 [sandboxd fdb145c](https://github.com/hky1999/sandboxd/commit/fdb145cf51f340dc46ebea3713c342b4ec93b127) 已普通推到个人 fork 的 codex/pr119-native-rwfs-rejoin-20261024。11 文件与远端 qa02 格式化/构建输入逐一核对 SHA，实际运行 ELF 仍为提交前构建的 debbf268…，没有将新构建冒充已测字节。VMM/内核/initrd/runsc/ADX 与 e3f402c 基线保持相同。

| 项目 | 通过范围 |
|---|---|
| 真实就绪门 | 新会话、路由、调度状态、公告资源、挂载、实际镜像/ELF 与 Secret 身份连续稳定后才发 SDK |
| 源码门 | 全仓 fmt/vet/test、相关三轮回归、server/network/FC race、生产构建；网络规则恢复旧代码先失败，新代码转绿 |
| 官方 SDK | FC 8+30、gVisor 8+30，共 76，无跳过 |
| 多代状态 | 两运行时各一实例三轮，完整 512 MiB 内存/64 MiB 根文件与进程身份验证 |
| 跨节点 | 两运行时 A→B/B→A 正常源退出和重新加入；另有 FC 两方向即时源节点退出，要求相同 Pod 身份和产品退休旧租约 |
| 恢复后持续写 | FC 真实 4 KiB 直接写/同步/读回，5 次保存/4 次恢复，跨节点两个分支各自继续写和再次保存 |
| 管理进程死亡 | FC/gVisor sandboxd 各一次 SIGKILL，原运行实例和未保存状态、两份快照保护引用、后续保存恢复均保留 |

进程死亡时 FC 仍有旧 checkpoint 输入打开；gVisor 当时输入已读完，不外推其后台读取尚未结束的情况。此前固定基线的 held-reader 测试另有记录。

## 关键数字与口径

同物理机逻辑双节点、2 GiB 配置内存、512 MiB 应用内存、64 MiB 根文件、1 GiB 私有盘、Full 内存保存、JuiceFS 无压缩/4 GiB 缓存/writeback=false。每组是一个实例的连续三轮，不是交替配对性能测量。

| FC 分相 | 本地私有盘历史样本 e3f402c | JuiceFS 私有盘当前样本 fdb145c 对应源码 |
|---|---|---|
| checkpoint 请求完成 | 8602 / 11223 / 11657 ms | 5185 / 7689 / 7856 ms |
| 私有盘保存 | 2863 / 3135 / 3298 ms | 15 / 14 / 15 ms |
| 当前内存保存 | 历史 5289 / 7746 / 8080 ms | 4847 / 7368 / 7556 ms |
| 每次 S3 PUT | 约 3 GiB | 约 2 GiB，普通运行写入另计 |

当前 guest 最大调度间隙仍约 4.87 / 7.38 / 7.57 秒；不能拿 14–15 ms 的盘克隆时间当作整个停顿。64 MiB 文件的 SDK 写入加 guest sync 约 513 ms，并非纯存储 fsync。gVisor 私有层未迁移，其三轮请求完成为 1531/1373/1594 ms。当前数据不支持稳定整体提速或超过竞品的结论。

## 新知识与保留失败

首次 SDK 76 项通过后，源重新加入因旧 TAP 租约缺设备失败。安全修复不能只忽略缺设备：先以运行时/PID/受管 cgroup 证明退出，在原 OCI 中退休资源归属，再持久化原池账，最后清退休日志；网络规则恢复也重新证明退出。覆盖五个落盘边界和迟到归还，避免误释放新使用者的同值资源。

第一次固定镜像滚动因 Pod 名变化触发基线状态清理，不能证明新代码恢复旧状态。因此保留该失败，改为在相同 Pod 中重放即时节点退出、恢复原故障，再移除临时覆盖并部署固定镜像。预检 helper 选错 Python 脚本的失败也保留；修正后仅操作本任务，未要求用户重复批准常规补齐。

## 遗留与下一步

1. 以相同代码和内存模式做 FC 本地私有盘与 JuiceFS 私有盘交替对照，包含普通写、小块同步写、停顿、完成、恢复读取量和 S3 总字节。
2. gVisor 原生克隆须独立适配与完整 bundle/SDK 验收；远端只读基线加本地差异层仍未实现，不能用 FC 结果代替。
3. 内存 Full 保存仍主导停顿；单独测一致捕获和远端提交，持久化成功确认不提前。
4. 生产容量准入、旧 Pod 状态清理后的孤儿归属回收、内部删除并发、真实物理故障域和存储 HA 仍未完成，不切默认后端。
